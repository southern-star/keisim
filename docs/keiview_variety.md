# KeiView の見た目を豊かにする設計書（標識の誤認識の試験と、季節・空・山）

KeiView の町を、アニメ調のまま、実際の日本の町に近づける計画です。2026-11-28 に、開発のできないノート PC で議論して書きました。**まだ何も実装していません。** 実装と学習は RTX 3060 の PC で行います。

- **目的は 2 つです。** ブラウザで人が見たときの説得力と、見た目が変わってもモデルが崩れないこと（強さ）です。写真のような描画や、実車・実カメラは目的にしません。
- **順番は、標識の誤認識の試験（T0〜T3）が先**で、季節・空・山（V0〜V3）がその後です。
- **T0 と V0 では絵を見せて止まり、T1 と V1 では数字を見せて止まります。** GPU で学習する T2 と V2 は、その後です。
- 新しい選択肢は、すべて既定でオフです。今の見た目（`plain` と `detail`）の画像・ラベル・評価の結果は、ビット単位で変えません。
- KeiSim の CPU 描画と、シミュレーターの世界（当たり判定、NPC、歩行者）は変えません。標識も季節も、KeiView の画像だけの話です。

読む順番: [roadmap.md](roadmap.md)（「KeiView の幻の赤」と「KeiView の評価は再現しない」）、[multicam.md](multicam.md)、[surround_rig.md](surround_rig.md)（360° の計画。`sky.js` などが重なる。5 章）、この文書。

## 2. 標識の誤認識の試験（T）

### 2.1 何を確かめるか

紛らわしい標識を置いて、モデルの運転と信号の読みがぶれないかを見ます。誤認識を 3 種類に分けます。

1. **標識を信号と見間違える**: 赤い標識を赤信号と読む（幻の赤）。緑や青の物を青信号と読む。
2. **自分に向いていない標識に反応する**: 横の道に向けて立っている進入禁止や止まれを、前を通り過ぎるときに見て止まる。
3. **運転に関係ない標識に反応する**: 駐車禁止は、走っている車には関係ありません。その近くでブレーキを踏めば誤認識です。

**いちばん危ないのは、赤信号を青と読む向き（信号無視）です。** 幻の赤は、要らない停止になります（roadmap の「KeiView の幻の赤」、town 1019 など）。

### 2.2 モデルの画像での大きさ

画像は 320×160 です。1 度あたりの画素は、広角（180° の円筒）が約 1.78、望遠（50°）が約 6.4 です。

| 物 | 大きさ | 20 m 先、広角 | 20 m 先、望遠 |
|---|---|---:|---:|
| 丸い標識（`roaddeco.js` の `signAt`） | 直径 0.6 m、高さ 2.35 m | 約 3 画素 | 約 11 画素 |
| 信号の灯（`signals.js` の 113 行目、半径 0.15 m を `sigscale` 2.2 倍） | 直径 0.66 m | 約 3.4 画素 | 約 12 画素 |
| 止まれ（白い縁、拡大なし） | 0.9 m | 約 4.6 画素 | 約 16 画素 |

- **モデルの画像では、灯と丸い標識がほぼ同じ大きさです。** ego と pilot のとき、信号は 2.2 倍に描かれます（`web/src/main.js` の 96 行目）。そのため実物の比（標識は灯の約 2 倍）が崩れています。
- 見分ける手がかりは、色、形（数画素では、ほぼ丸い点）、置かれた場所と高さ、信号の黒い箱です。数字や文字は読めません。
- 標識の大きさは 2 通り試します（`sign_scale`）。実寸（1）と、`sigscale` に合わせる（2.2。実物の比を保つ）です。

### 2.3 足す標識と物

| 種類 | 見た目 | 置く所 | 意味 | 試す誤認識 |
|---|---|---|---|---|
| 進入禁止 | 赤い丸に白い横棒 | 実在の町の一方通行の、出口側の端。逆向きに入ろうとする車に向ける | 入れない（KeiSim の一方通行と一致） | 1、2 |
| 一方通行 | 青い長方形に白い矢印 | 実在の町の一方通行の、入口側 | 一方通行（一致） | 1（青） |
| 最高速度 | 今の `roaddeco.js` と同じ | 今と同じ（道の制限速度から数字を取る） | 一致 | 1 |
| 駐車禁止 | 今と同じ | 今と同じ（幹線以外の、60 m より長い道の、向きごとに 3 割） | 運転には関係ない | 3 |
| 横断歩道 | 今と同じ（青い四角） | 今と同じ | 横断歩道の予告 | 1（青） |
| 信号機ありの警戒標識 | 黄色のひし形に、赤・黄・緑の灯の絵 | 信号のある交差点の 50〜100 m 手前 | 予告（本当に信号がある所にだけ） | 1（いちばん紛らわしい） |
| 案内標識 | 大きな青い板に、白い文字（架空の地名）と矢印 | 幹線の、信号のある交差点の手前。道の上に張り出す | なし（飾り） | 1（青。信号の近くの高い所） |
| 国道の番号、地名の板 | 青い逆三角に白い数字。白い板に黒い文字（架空の地名） | 幹線の道ばた、交差点の角 | なし（飾り） | 3 |
| 赤と緑の物（`hard` だけ） | 郵便ポスト、のぼり旗、自販機（実在の会社の名前や印は使わない） | 道ばた、交差点の角 | なし | 1 |

置き方は 2 段階です。

- `real`: 本物らしい場所と数。
- `hard`: `real` に加えて、意地悪な場所に置きます。
  - 信号の柱と腕（灯の横や下。日本でよくある付け方）。
  - 停止線の近くで、灯と同じ高さ。
  - 赤と緑の物も足す。

**意味のある標識は、KeiSim の規則と合う所にだけ置きます。** 対象は、進入禁止、一方通行、最高速度、止まれ、信号機ありです。合わない標識を学習で見せると、モデルは「この標識は無視してよい」と覚えます。

- 一方通行は、実在の町（`keisim/realworld.py`）にしかありません。生成した町にはないので、進入禁止と一方通行は実在の町にだけ立ちます。
- 一方通行と止まれの多い西大井（`osm_nishioi`）が、いちばんよい試験の場です。

### 2.4 作り（T0）

- **新しいモジュール `web/src/world/signs.js`**:
  - `?signs=off|real|hard`（既定は `off` で、モジュールを読み込まない）と `?signscale=`（既定 1）で切り替えます。
  - `signs` がオフでないときは、`signs.js` が柱の標識を全部立て、`roaddeco.js` は柱の標識を立てません（重なりを避けるため）。`signs=off` のとき、`roaddeco.js` の出力は今とビット単位で同じにします。
  - `roaddeco.js` の `signAtlas` と `signAt` を使い回すなら、関数を書き出すだけにして、`detail` の画像が変わらないことを確かめます。
- **意味ラベル**: 標識の板と柱は、今の `roaddeco.js` と同じく `SEM.pole` にします（`web/src/ego.js` の 10〜13 行目、`roaddeco.js` の 580 行目）。
  - **新しいクラスは足しません。** KeiSim の `SEM_NAMES` と同じクラスを使っているので、足すとモデルの出力の形が変わります。
  - 灯は `tl_red` などに分類されるので、セグメンテーションの損失が「赤い丸い板は灯ではない」ことを画素ごとに教えます。
- **エピソードごとの出し入れ**: 標識は町を読むときに作ります。静的なまとめ描き（`batch2.js`）には入れず（`ctx.noBatch`）、エピソードごとに見せるか隠すかを切り替えます。
  - これで、収集のときに「標識あり」の割合を決められます（2.6）。
  - 乱数は、太陽の向きと同じく自分の列から引きます（太陽は `[episode_seed, 7707]`、標識は例えば `[episode_seed, 7708]`）。
- **標識の位置を Python に返す**: 町を読んだ応答（`keiview.py` の `load_town`）に、標識の一覧を入れます（種類、KeiSim 座標、向き、高さ、大きさ）。`KeiViewRenderer` がこれを持ち、評価で「標識が見えているフレーム」を数えるのに使います（2.5）。
- **設定**:
  - `keisim/config.py` の `keiview_roads` の隣に、`keiview_signs = "off"` と `keiview_sign_scale = 1.0` を足します。
  - `scripts/collect.py`、`scripts/evaluate.py`、`scripts/demo.py` に `--keiview_signs` と `--keiview_sign_scale` を足します（`--keiview_roads` と同じ作り）。
  - 評価の出力の名前に `_kvsigns` を足します（`evaluate.py` の 638 行目の `_kvdetail` と同じ作り）。
- **KeiSim の世界には標識を足しません**: 標識は、今の `roaddeco.js` と同じく車道の外の縁石側に立てます。KeiSim の歩行者は柱を通り抜けますが、映るのは一瞬なので気にしません。

#### G0-T で見せるもの（絵と数字を見せて止まる）

1. **今の見た目が変わらないこと**: `signs=off` で、`plain` と `detail` の画像が main とビット単位で同じであること（`web/tools/golden.mjs`、`tools/keiview_hash.py`）。mc14 の評価の数本が同じ結果になること。
2. **絵**: 格子の町、札幌、西大井、大きな交差点の街で、`real` と `hard` を 2 通りの大きさで見せます。ブラウザの大きな画面（1280×720）と、モデルの画像（320×160 の広角と望遠）の両方です。
3. **速さ**: 1 フレームの描画時間（RTX 3060）。

### 2.5 mc14 の誤認識を測る（T1、学習なし）

**指標**:

- **信号の読みの表**: フレームごとに、真の信号（`tl_gt`）とモデルの読み（`tl_pred`）を突き合わせた、4×4 の数の表です。モデルの読みは `keipilot/model.py` の `tl_head` の出力で、赤・黄・青・なしの 4 クラスです。
  - 今の `evaluate.py` もフレームごとに記録していますが（274 行目と 317 行目）、書き出すのは失敗したルートの窓だけです。全部のフレームの表を、ルートの結果に足します。
  - 幻の赤（信号なし）: 真は「なし」、読みは赤。
  - 幻の赤（青のとき）: 真は青、読みは赤か黄。
  - **赤の見落とし**: 真は赤、読みは青か「なし」。いちばん危ない向きです。
  - `scripts/collect.py` にも、似た数え方がもうあります（`lead_edge_tl_none_red`、563〜573 行目。信号のない所でモデルが赤と読んだフレーム）。
- **標識が見えているフレームとの比較**: 上の表を、標識が見えているフレームとそれ以外に分けます。見えているフレームとは、2.4 の一覧の標識が、広角の画角の中の 40 m 以内にあるフレームです。標識の種類ごとにも分けます。
- **要らない停止**: 交差点ごとの `needless_s`（`evaluate.py` の `junction_passes`、352 行目）に加えて、交差点の外の要らない停止（モデルは止まっているのに、エキスパートは秒速 1 m より速く進みたいとき）を足します。
- **標識の近くの減速**: 標識が見えているフレームで、モデルの目標速度がエキスパートより秒速 2 m 以上低い秒数です。
- **今までの指標**: 完走、衝突、信号無視。

### 2.6 標識を入れた学習（T2）

- **収集**: KeiView で描くエピソードの一部（案: 6 割）で標識を見せ、残りは今の見た目のままにします。
  - DAgger では mc14 が運転するので、mc14 が標識で誤認識した場面が、そのまま学習データになります。
  - ラベル（エキスパート）は標識を見ないので、変わりません。
- **学習に入れない標識**: 2 種類（案: 信号機ありの警戒標識と案内標識）は学習に出さず、評価だけに使います。
  - 見たことのない紛らわしい物でも誤認識しなければ、標識を覚えたのではなく、本当に強くなったと言えます。
  - この 2 種類は、次の回で学習に入れます。
- **学習**: mc14 から、今までの回と同じ大きさで学習します（4 × 20 万サンプル）。
- **時間**: 標識の描画はほとんど重くならない見込み（G0-T で測る）なので、mc13 の回と同じ約 34 時間です（roadmap）。

#### G2-T

- T1 の表で、誤認識が減ること。学習に入れなかった 2 種類でも減ること。

## 3. 季節・空・山（V）

### 3.1 足すもの

| | 中身 | 作り | 手間 |
|---|---|---|---|
| 季節 | 春（今）、夏（桜は緑の葉）、秋（赤と黄の葉）、冬（葉のない枝）。草地の色も季節で変える。生け垣は常緑なので変えない | 桜の色は、4 段の色の表（`sakura/tree.js` の 32〜36 行目の `BANDS`）を季節ごとに差し替える。冬は、葉の塊と葉の板を隠す | 中。葉の塊の材質は、作るときに `BANDS` の色を受け取る（`sakura/materials.js` の 173〜177 行目。uniform かどうかは V0 で確かめる）。葉の板の色は頂点に焼き込まれ、逆光の縁の光はピンクがシェーダーに書き込まれている（同じファイルの `rimChunk`）。エピソードごとに変えるには、どれも uniform で変えられる作りに直す |
| 空 | 今の筋雲、入道雲（夏）、曇り（灰色。日差しを弱め、影を薄くする） | `sky.js` のシェーダーに、雲の種類の値を足す。曇りは、太陽と空の光の強さも変える | 小〜中 |
| 山 | 町の外側の遠くに、木に覆われた低い山並み。方向と高さはエピソードごとに変える | 新しいモジュール。距離は 400〜1500 m あたり | 中 |

**山の注意**:

- 町のもや（`FogExp2`、既定の濃さ 0.0026、`sky.js` の 96 行目）は距離の 2 乗で効きます。600 m 先では約 9 割がもやの色になり、山はほとんど見えません。山には町のもやを使わず、自分で空の地平線の色へ薄めます（参考画像のような、青みがかった遠い山）。
- 深さの画像は、400 m（`DEPTH_FAR`、`web/src/unproject.js` の 9 行目）より遠いと 0（空と同じ）になります。山の意味ラベルは `terrain` にします。KeiSim の CPU 描画には山はありません。
- 山は町に影を落としません。カメラが描く距離は 2500 m（`web/src/ego.js` の 211 行目）で、空の球は半径 1800 m です。山はその内側に置きます。

夕方（低い太陽）は後に回します。影が長くなって、影の範囲（`shadowSize`）の外にある物の影が切れるからです。

### 3.2 作り（V0）

- **設定**: `keisim/config.py` に `keiview_look = "off"`、`collect.py`、`evaluate.py`、`demo.py` に `--keiview_look` を足します。
  - 値は `off`、`random`、評価用の固定の組み合わせ（例: `summer`、`cumulus`、`mountains`）です。
  - ブラウザでは `?look=` で選べるようにします。
- **エピソードごとの送り方**: 太陽の向きと同じ仕組みで、`look`（季節、空、山）を送ります（`keiview.py` の `new_episode` と、描く要求の `light`）。
  - 乱数は自分の列から引きます（例: `[episode_seed, 7709]`）。
  - **オフのときは乱数を引かず、要求にも入れません。** 今の画像をビット単位で同じに保つためです。
- **町は読み直さない**: 季節・空・山は、町を読み直さずに切り替えます。町の読み込みは重く、`keiview.py` は同じ町なら読み直しません。
- **屋根と壁の色の幅は V では触らない**: 家の生成器の色の表（`houses/tex.js`）で町ごとに決まる話なので、後の段階に回します。

## 5. 守ること

- **既定はオフ**: `signs=off`、`look=off` で、`plain` と `detail` の画像・ラベル・評価が main とビット単位で同じであること。新しい乱数は自分の列から引き、シミュレーターと太陽の乱数を変えません。
- **意味のある標識は、KeiSim の規則と合う所にだけ置く**（2.3）。
- **新しい意味ラベルのクラスは足さない**（2.4）。
- **KeiSim の CPU 描画とシミュレーターの世界は変えない。**
- **実在の会社の名前や印は描かない**（自販機、看板）。地名は架空にします。
- **360° の計画（surround_rig.md）との重なり**: 同じファイルを触ります。先に始めたほうを main に入れてから、もう片方を始めます。
  - `web/vendor/sakuragaoka/core/sky.js`: 360° の S0 は影の範囲を置き直し、V0 は雲の種類を足します。
  - `web/src/ego.js`: 360° の S0 は影の地図、V0 は `look` の切り替えです。
  - `keisim/render/keiview.py`: 360° の S0 は `_render_rig`、この計画は `new_episode` と `load_town` です。

## 6. ユーザーに決めてほしいこと

1. **学習の回**: T2 と V2 を 1 回にまとめるか、別にするか。さらに、360° の S3 や保留中の mc15（路上駐車の DAgger）ともまとめるか。
   - まとめると GPU の日数は減りますが、効き目が混ざります。
   - ただ、どれも既定オフの切り替えなので、評価のときに切り替えれば、効き目を分けて測ることはできます。
2. **標識の大きさ**（実寸か、`sigscale` に合わせるか）: T1 の数字を見て、G1-T で決めます。
3. **学習に入れない標識と季節**: 案は、信号機ありの警戒標識・案内標識と、秋です。
4. **ブラウザの既定**（T3、V3）: 学習のあと、新しい見た目を既定にするか、選べるだけにするか。
