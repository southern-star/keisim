## 方針

次は、2 本の柱で進めます。

1. **複雑な交差点**: 大きな交差点 (スクランブル、右折専用車線)、横断歩道を渡る人、見えにくい右折、矢印の信号。
2. **自転車**: 道路の左端を走る自転車から始めて、歩道を走る自転車、二段階右折へ。

どちらも、まず今ある要素を KeiPilot Mc に学ばせ、そのあと足りない要素をシミュレーターに足します。

## 決めたこと

- **次の学習の回は 1 回にまとめる**: 横断歩道 (PR #31)、大きな交差点の街 (PR #33)、自転車 (PR #35) を、mc12 (v0.11.0) から 1 回の学習 (mc13) で学ばせます。
  - どの要素にも専用の評価スイートがあるので、効果は要素ごとに分けて見えます。
  - 今までの力が落ちていないかは、今までのスイートで確かめます。
- **自転車の巻き込みは、カメラに映る自転車だけで判断させる**: Mc の 2 台のカメラは前向きなので、左後ろから来る自転車は見えません。
  - エキスパートのラベルがカメラに見えないものに従うと、モデルは見えない相手を待つことや避けることを覚えます ([multicam.md](multicam.md) の 3 章、8 回目)。
  - 見えない巻き込みは、後ろのカメラと同じく、当面は受け入れます。
- **新しい選択肢は、既定でオフにする**: オフのとき、今までの街・エピソード・ラベルがビット単位で変わらないことを、main とのハッシュの比較で確かめます。今までの学習データと評価の数字を守るためです。

## 2b. 右折の向かい合いをねらった回 (mc14rt、採用せず)

- [x] `evaluate.py` の行き詰まりの原因に「向かい合い」(standoff) を足しました。
  - 自車が交差点の中で、自車を待つ車の進路に立っている場合です。シミュレーターはどちらも動かしません。
  - 前の回の行き詰まりを走らせ直して数えました (`tools/standoff_recount.py`)。KeiSim の 740 ルートでは mc13 11 件、mc12 5 件、mc11 3 件。片側 2 車線だけで mc13 は 7 件です。
- [x] 向かい合いの場面の DAgger で mc13 から学習しました ([multicam/rounds/round13rt.sh](multicam/rounds/round13rt.sh))。
  - できた mc14rt は、どのスイートの組でも mc13 と差がありません。
  - 向かい合いも減っていません: 片側 2 車線で 7 件対 7 件、新しい種の片側 2 車線 (`suburban2` など) で 4 件対 4 件です。
- 向かい合いの起き方は 2 通りです。
  - 譲ると決めるのが手本より 0.3〜0.5 秒遅れ、1〜2 m 深く止まる。鼻先が対向車線にかかり、対向車がその前で止まる。
  - 出口の詰まった交差点に、青で入っていく。
  - 向かい合ってからは手本も待つので、DAgger のラベルからは抜け方を学べません。
- PR #51: 手本が右折で 2 m 手前で待つ形 (`--expert_wait_back 2`) と、手本に遅れを入れる評価 (`--expert_delay`)。0.4 秒遅れた手本の向かい合いが 22 件から 2 件に減りました。学習に使うと、今までの右折のラベルと食い違うので、まだ使っていません。

## 残タスク

### KeiPilot Mc の弱点 ([multicam.md](multicam.md) の 5 章)

- [ ] **駐車車両に近づきすぎて止まり、よけて出るときに当たる** (2c、v0.12): 駐車車両のすぐ後ろで止まってから出て、角に当たります。対向車があって手本が待つ場面で出ることもあります。
- [ ] **手本なら進める場面で止まり続ける** (v0.12): KeiView の大きな交差点で、信号を正しく読んだまま青のあいだも止まっています (20 ルート中 5 本、mc13 は 1 本)。モデルの目標速度そのものが 0 です。KeiSim の片側 2 車線の、信号のない合流や交差点の中でも 6 本あります。
- [ ] **右折で深く止まって、対向車と向かい合う** (2b): DAgger では減りませんでした。
  - 候補: 手本が右折で待つ位置を 2 m ほど手前にして、モデルの行き過ぎに余裕を持たせる (ラベルが変わるので、集め直しが要る)。
  - 候補: 交差点の中で横向きの車に道をふさがれた対向車が、もっと手前で止まる (シミュレーターの側。モデルの失敗が見えにくくなる)。
- [ ] **青で発進したら、交差点の先が詰まっていた**: いちばん多い衝突で、大きな交差点ではさらに大事になります。向かい合いの 2 つ目の起き方でもあります。
  - 候補: 交差点の先の詰まりを当てる補助の出力と、青の発進のときだけ働く、止まるための安全層。
- [ ] **赤で止まっているのに出る、黄を青と読む**:
  - 候補: 止まっていて赤が確かなら速度を 0 にする、厳しい RedHold。
  - 幻の赤で止まったままになるルートがどれだけ増えるかを、全部の評価で測る必要があります。
- [ ] **札幌の優先道路で譲り損ねる**: KeiSim の 300 ルートの衝突が、回ごとに少しずつ増えていました (mc8 の 2 件から mc12 の 7 件。mc13 は 3 件、mc14rt は 2 件、mc14 = v0.12 は 0 件)。YieldHold の条件をどこまで緩めるかの綱引きです。
- [ ] **歩行者**: ブレーキが約 1 秒遅い。横断歩道で譲らない (上の mc13)。
- [ ] **KeiView の幻の赤**: 青を赤と読んで、止まったままになります (town 1019 など)。
- [ ] **横や後ろからの割り込み**: 後ろのカメラは保留中です。
