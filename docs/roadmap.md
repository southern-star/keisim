# 今後の方針と残タスク

2026-11-13 時点の方針と、残っている作業の一覧です。進んだら、このファイルを書き直します。

## 方針

次は、2 本の柱で進めます。

1. **複雑な交差点**: 大きな交差点 (スクランブル、右折専用車線)、横断歩道を渡る人、見えにくい右折、矢印の信号。
2. **自転車**: 道路の左端を走る自転車から始めて、歩道を走る自転車、二段階右折へ。

どちらも、まず今ある要素を KeiPilot Mc に学ばせ、そのあと足りない要素をシミュレーターに足します。

## 決めたこと

- **次の学習の回は 1 回にまとめる**: 横断歩道 (PR #31)、大きな交差点の街 (PR #33)、自転車 (PR #35) を、mc12 (v0.11.0) から 1 回の学習 (mc13) で学ばせます。
  - どの要素にも専用の評価スイートがあるので、効果は要素ごとに分けて見えます。
  - 今までの力が落ちていないかは、今までのスイートで確かめます。
- **自転車の巻き込みは、カメラに映る自転車だけで判断させる**: Mc の 2 台のカメラは前向きなので、左後ろから来る自転車は見えません。
  - エキスパートのラベルがカメラに見えないものに従うと、モデルは見えない相手を待つことや避けることを覚えます ([multicam.md](multicam.md) の 3 章、8 回目)。
  - 見えない巻き込みは、後ろのカメラと同じく、当面は受け入れます。
- **新しい選択肢は、既定でオフにする**: オフのとき、今までの街・エピソード・ラベルがビット単位で変わらないことを、main とのハッシュの比較で確かめます。今までの学習データと評価の数字を守るためです。

## 残タスク

### KeiPilot Mc の弱点 ([multicam.md](multicam.md) の 5 章)

- [ ] **青で発進したら、交差点の先が詰まっていた**: いちばん多い衝突で、大きな交差点ではさらに大事になります。
  - 候補: 交差点の先の詰まりを当てる補助の出力と、青の発進のときだけ働く、止まるための安全層。
- [ ] **赤で止まっているのに出る、黄を青と読む**:
  - 候補: 止まっていて赤が確かなら速度を 0 にする、厳しい RedHold。
  - 幻の赤で止まったままになるルートがどれだけ増えるかを、全部の評価で測る必要があります。
- [ ] **札幌の優先道路で譲り損ねる**: KeiSim の 300 ルートの衝突が、回ごとに少しずつ増えています (mc8 の 2 件から mc12 の 7 件)。YieldHold の条件をどこまで緩めるかの綱引きです。
- [ ] **歩行者**: ブレーキが約 1 秒遅い。横断歩道で譲らない (上の mc13)。
- [ ] **KeiView の幻の赤**: 青を赤と読んで、止まったままになります (town 1019 など)。
- [ ] **横や後ろからの割り込み**: 後ろのカメラは保留中です。
- [ ] **ブラウザの town 2002**: 1 度、右折の途中で止まったまま動きませんでした。原因はまだ調べていません。
