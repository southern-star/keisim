# 東京の住宅地の候補地調査 (道路 LOD3 と一方通行)

調査日: 2026-10-25。目的は札幌の次の実在の町で、条件は「PLATEAU の道路 LOD3 (停止線・横断歩道・車線境界線の実位置) がある」「一方通行が少ない」「片側 1 車線の対面通行が主」「平坦」。

**結論: 条件を全部満たす場所は東京にはありません。** 道路 LOD3 は都心に集中し、LOD3 のある住宅地は一方通行が 3 割以上です。一方通行の少ない区画整理地 (江戸川区など) には LOD3 がありません。妥協点は次の 2 つです。

1. **品川区 西大井・二葉** (北緯 35.616〜35.625、東経 139.723〜139.734): 住宅地で唯一、路面 LOD3 が面で揃う (1 km 角の 50 m 格子の 65% に路面の実形状、有楽町は 99%)。一方通行は長さの 28〜34%。読み込み器に「片側 1 車線だけの道路」を足せば使えます。
2. **江戸川区 瑞江・南篠崎** (北緯 35.683〜35.695、東経 139.895〜139.910): 札幌と同じ統計 (一方通行 9%、3 車線以上 0%、平坦、区画長 59 m)、止まれの標識が OSM に 52 か所。道路は LOD1 のポリゴン (実際の道幅) と建物 LOD2 のみで、標示の実位置はありません。

## 3. 判断の材料

- **標示の実位置が最優先なら品川区 西大井・二葉。** 車線境界線・停止線・横断歩道・島が LOD3 にあり、信号機・標識・電柱の都市設備 LOD3 も揃っています。代わりに、一方通行 (長さの 3 割) を読み込み器が扱えるようにする必要があります (片側 1 車線だけの道路: 多車線化よりずっと小さい拡張)。坂も 10 m ほどあります (KeiSim は平面なので無視できますが、見た目は違います)。
- **一方通行の少なさと平坦さが最優先なら江戸川区 瑞江・南篠崎。** 札幌とほぼ同じ統計で、読み込み器はそのまま使えます。道路 LOD1 のポリゴンで実際の道幅が取れ、建物は LOD2 (2025 年) です。停止線・横断歩道は OSM の止まれ 52 か所を手がかりに合成することになります。
- 新宿区 北新宿は、一方通行の対応を入れる前提なら第 3 候補です (41%)。

## 4. 方法と再現

- Overpass: 矩形ごとに `highway` の way と信号・止まれ・横断歩道のノードを取得し、一方通行と 3 車線以上を道路長で集計 (`tools/site_survey/tokyo_stats.py`)。
- PLATEAU: データカタログ API から各区の 3D Tiles を辿り、タイルの領域 (`boundingVolume.region`) と、b3dm 先頭の Range 要求で取った `BATCH_LENGTH` から 1 km 格子の地物密度を出す (`lod3_where.py`、`lod3_grid.py`、`b3dm_meta.py`)。
- 実被覆: Draco を復号 (DracoPy) して頂点を緯度経度に直し、矩形内の 50 m 格子のうち路面の頂点があるものの割合 (`draco_verify.py`)。
- 道路 LOD1/LOD2 (MVT): z=16 のタイルを取って層ごとの地物数を数える (`mvt_cover.py`)。
